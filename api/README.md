# API and workers
One NestJS package with two entrypoints: `src/main.ts` for HTTP and `src/worker.ts` for background work.
Both import the same DomainModule and InfrastructureModule. Only WorkerModule registers
workers/processors; HTTP startup never starts job consumers.

The worker runs `ChainSubmitWorker` (`src/domain/credits/chain-submit.worker.ts`), which polls
`operations` for `CREDIT_EARN_CHAIN_SUBMIT` rows and dispatches them to the `octap` Sui package via
`src/infra/clients/sui`. That client is imported only by `worker.module.ts`, never by
`infra/infrastructure.module.ts`, so the issuer signer (an AWS KMS key; `docs/kms-signer.md`) is never
reachable from the HTTP process. See the root `.env.example` for the `SUI_*` variables it needs and
`docs/roadmap.md`'s known gaps for what's still missing.

## Layers

| Directory | Contains |
| --- | --- |
| src/api/rest | Controllers: protocol mapping only, no business rules |
| src/api/dto | Request body types |
| src/domain/<feature> | Use-case services and the feature's Nest module |
| src/infra/db/schema | Drizzle table definitions and relations |
| src/infra/db/repositories | Persistence for each feature |
| src/infra/db/rls.ts | RLS helpers: `withTenant` (tenant role and organization, restored when nested), `asOwnRole`, `withRls` |
| src/infra/clients/<vendor> | Vendor adapters (e.g. `sui`); import into `infra/infrastructure.module.ts` unless, like `sui`, the vendor's credentials must stay worker-only |
| src/infra/auth | API-key guard, scopes, credential issue/rename/revoke (applied globally via `APP_GUARD`) |
| db/postgres/migrations | Migrations generated by `npm run db:generate` |

Create other folders (config, observability, vendor clients, queue, workers) when the first
feature needs them; see [the implementation guide](../docs/implementation-guide.md) and
[the roadmap](../docs/roadmap.md).

From the root: npm run start:api or npm run start:worker. From api/: npm run start or npm run start:worker.
Both require a root build first because API uses the shared contracts workspace.

## Calling the API

Every route requires `Authorization: Bearer <api key>`. The tenant is always resolved from the
matched credential, never from a client-supplied header — an `x-organization-id` header is
accepted only as a client-side sanity check and is rejected if it disagrees with the key. The
first credential for a new organization is issued out of band (there is no bootstrap endpoint,
since calling one would itself need a key): `npm run seed:dev-credential -- <organizationId>`.
That key carries the `admin` scope, which webhooks and the refund policy need; only the script
issues `admin` keys. An Owner or Business Developer issues, renames and revokes keys from the
console session (`read` by default; only the Owner issues or manages `write` keys): `/v1/console/organizations/:organizationId/api-credentials`.
An API-key route authorizes by the key's scopes only, never by the role of whoever created the key.

The console session also manages the reward catalog at
`/v1/console/organizations/:organizationId/vouchers`: the Owner or a Business Developer lists and
reads it; only the Owner creates, edits, pauses and activates. A console create is always a `DRAFT`
(activated afterwards with a PATCH) and must send `pointsCost`; `/v1/rewards/vouchers` keeps its own defaults.

## API docs

The OpenAPI document is built from the controllers (`src/api/openapi/openapi.document.ts`). Each
route's auth (merchant API key, console user, public) and required scopes are read from the same
metadata the guards enforce, so a new route needs no swagger decorator to be listed correctly.

- Set `OPENAPI_ENABLED=true` to serve Swagger UI at `/docs` and the spec at `/docs/openapi.json`.
  It is off by default; leave it off in production.
- `docs/openapi.json` (OpenAPI 3.1) is the committed copy for frontend, Postman and client
  generators. CI runs `npm run openapi:check` and fails when any generated file is stale.
- Request bodies, query objects and responses come from each handler's own TypeScript types,
  declared or inferred: `npm run openapi:schemas` writes `src/api/openapi/route-types.generated.ts`
  (one alias per route, so `npm run typecheck` breaks if a handler changes without regenerating)
  and `route-schemas.generated.ts` (JSON Schemas from the type checker). Type a new `@Body()` or
  `@Query()` with a real type, not `Record<string, unknown>`; for console and platform bodies the
  service validates by hand, declare `Wire<SomeContractType>` from `src/api/dto/console.dto.ts`.
- After changing a route or a wire type: `npm run openapi:schemas && npm run build && npm run
  openapi:generate`, then commit the three generated files.
